# 优先排查可观测原因

| 现象 | 先查 | 避免 |
|---|---|---|
| 缺节点或 UNKNOWN | 实际后端/端口、版本、object_info 与核心节点 | 为核心节点盲装大量插件 |
| 缺模型但节点正常 | 目录、扩展名、哈希与加载器文件枚举；刷新/重启后重新选择 | 把缺文件说成缺插件 |
| Could not detect model type | 架构、量化格式、下载完整性、兼容版本 | 改名假装另一个格式 |
| LoRA 不生效 | 有效接线、非零强度、目标模块匹配、真实触发词 | 仅提高 CFG 或按文件名猜触发词 |
| lora key not loaded | 键名前缀、底模/层映射、原生 ComfyUI 格式与版本 | 忽略警告宣称已生效 |
| 秒出相同图片 | 种子是否不变、execution_cached、是否真正进入采样 | 重装模型或把缓存当新图 |
| 黑白图/花屏 | 输出像素、实际 VAE、日志、精度与模型匹配 | 无证据认定内容过滤或显卡太差 |
| CUDA OOM | 其他 GPU 任务、batch、尺寸、卸载与 RAM | 无授权杀进程或声称只要 12GB 一定能跑 |
| 很慢但步数推进 | CPU offload、RAM/换页、磁盘、其他任务 | 反复提交同一任务 |
| comfy_aimdo 等模块缺失 | 代码与同一 Python 的 requirements 是否同步 | 用系统 pip 安装未知同名包 |
| 依赖冲突 | 旧插件对 transformers 等的约束，是否应隔离环境 | 看见 Successfully installed 就忽略冲突 |
| SQLite in_use | 同一安装是否重复启动、原任务是否运行 | 删除数据库、强杀所有 Python |
| 网页能开但选项不对 | 网址对应的目录、版本和模型搜索路径 | 不断新开不同端口让用户迷路 |
| 下载文件仅几 KB | 登录页、错误页、LFS 指针、下载是否完成 | HTTP 200 就当下载成功 |

需要同步依赖时用该安装的 Python；PATH 脚本警告与致命导入错误区分。nvidia-smi 的 CUDA 字段不是当前 Python runtime 的版本，需检查 torch.cuda 与设备实际识别。

固定种子用于对照，其他条件不变时返回缓存是正常的。randomize/increment/decrement 是前端控制；API 客户端需主动修改 seed。控件可能在提交前后更新，上一张图的实际种子从 prompt/history/PNG 元数据核对，不靠当前显示数字猜。

采样时间不能作为画质证明，步数不是越多越好。调整一次一个变量；记录是否偏离基准。遇到显存不足，可以向用户说明并在副本降低尺寸或 batch，但不能称为原参数已验收。尺寸保持合理比例与 16 的倍数。

提交 API 后以 prompt_id 关联执行、history 和输出；轮询超时先查队列，不代表任务已停止，也不应立刻重复提交。打开真正保存的 PNG，确认像素与目标尺寸；任务成功不等于用户满意。

连续尝试没有新的诊断依据时停止扩大改动，报告已经验证到哪一步、目前根因证据与需要的用户操作。不绕过安全组件，不以安装其他模型转移问题。
